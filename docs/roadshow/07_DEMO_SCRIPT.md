# Prototype 演示脚本

> A 股界面、fixture 与状态机：`IMPLEMENTED · MOCK`  
> 千问、百炼、魔搭与外部工具：`PLANNED · NOT CONNECTED`

## 演示目标

90 秒内只证明三件事：

1. 不同来源由不同 Agent 负责；
2. 每个结论能回到证据，冲突不会被抹平；
3. 来源失败时系统会安全降级，不荐股、不交易。

不要现场解释代码、JSON Schema 全字段或每个按钮。

## 推荐场景

使用固定的虚构 A 股事件：

> 沪市样本 A 发布业绩预告修正，同时公开热度源将指标变化夸大为“经营失速”。

页面始终显示：

- `A 股演示`
- `MOCK DATA`
- `不构成投资建议`

## 90 秒现场路径

| 时间 | 操作 | 主讲旁白 |
| ---: | --- | --- |
| 0–10 秒 | 打开风险监控台，指向 MOCK 标识和虚拟持仓图 | “这是固定 A 股演示数据，不接账户，也不读取实时行情。” |
| 10–22 秒 | 选择“业绩预告修正”事件并开始 | “同一事件被拆给中文舆情和公告数据两个专项 Agent。” |
| 22–35 秒 | 观察两个 Agent 逻辑并行、分别提交 | “它们使用同一合同，但来源命名空间互相隔离，不能改写对方结论。” |
| 35–50 秒 | 打开右侧完整报告 | “这里将事实、推断和未知项分开，每条发现都保留证据 ID、时间和来源等级。” |
| 50–63 秒 | 展示主管综合 | “公告确认了指标变化，但‘经营失速’的热搜措辞缺少一级来源，所以主管降低措辞强度，而不是把热度当事实。” |
| 63–78 秒 | 切换“来源超时”或“证据冲突”故障 | “当来源缺失或冲突时，系统暂不估计影响，进入等待核验或隔离状态。” |
| 78–90 秒 | 打开最终报告，点击“标记已阅读” | “风险 Agent 只解释并给出核验清单，最终按钮只记录阅读，永远不会下单。” |

## 75 秒压缩版

如果前五页超时：

1. 10 秒：MOCK 标识与 A 股事件。
2. 20 秒：两个专项 Agent 并行。
3. 20 秒：完整报告和证据 ID。
4. 15 秒：故障注入与安全降级。
5. 10 秒：人工门禁与非交易声明。

## 建议画面

### 主页面

- 虚拟持仓环形图或堆叠条形图；
- 事件／故障标签；
- 风险状态采用统一颜色语义；
- 不显示未经解释的目标仓位。

### 完整报告抽屉

保留团队认可的右侧弹出形式：

- 已确认事实
- 推断
- 未知项
- 证据引用链
- 下一步核验清单

### 指标折线图

只展示模拟指标和用户预设关注线：

```text
模拟指标变化 → 穿越关注线 → 触发“需要核验”
```

不要将关注线说成市场预测，也不要据此给买卖建议。

## 故障选择

现场只演示一个最强故障，推荐“来源超时”：

- 状态直观；
- 不需要解释复杂金融事实；
- 能证明单点失败不会污染另一条证据链；
- 最终风险显示“暂不估计”。

“证据冲突”和“热搜传闻隔离”可留给答辩或备用录屏。

## 现场常见追问

**这是真实 Agent 吗？**  
当前是逻辑 Agent 和确定性状态机，流程、合同与故障治理已实现；在线模型调用是下一阶段。

**为什么不用一个大模型？**  
分开来源责任可以保留证据边界，并定位错误发生在哪一步。

**为什么不直接给操作建议？**  
项目定位是风险信息核验，不是持牌投资顾问；系统必须把决定交还用户。

**如果 MCP 或数据源掉线呢？**  
连接器状态显式降级，已有证据保留，缺失来源进入 gaps，不能用模拟内容冒充实时结果。
