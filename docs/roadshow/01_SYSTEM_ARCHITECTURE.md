# 系统架构｜从本地原型到阿里生态目标方案

> 当前状态：`IMPLEMENTED · MOCK`  
> 阿里生态联动：`PLANNED`

## 一句话架构

OrgLab Sentinel 把**来源采集、证据判断、冲突治理、风险解释和用户决策**拆成可审计的层级；A 股只是首个路演场景，核心工作流不依赖某一个市场。

## 当前仓库架构

```text
浏览器
└── React/Vite 界面
    ├── 风险监控台
    ├── Agent 团队
    └── 组织实验室
        ↓
JavaScript 确定性状态机
        ↓
固定 MOCK 场景与故障注入
        ↓
EvidenceBrief / SupervisorSynthesis / UserRiskReport
        ↓
Patch 证据账本与用户“已阅读”门禁
```

| 层 | 当前实现 | 边界 |
| --- | --- | --- |
| 体验层 | 三个可点击页面、右侧完整报告、状态卡片 | 浏览器内运行 |
| 编排层 | 六阶段确定性状态机 | 不是真实模型并发 |
| Agent 层 | 四种逻辑职责与固定输出 | 不是真实在线 Agent |
| 数据层 | 本地 fixture | 无实时数据 |
| 合同层 | 版本化 JSON Schema 与测试 | 权限目前是合同约束，不是后台强制 |
| 治理层 | 冲突隔离、故障降级、人工确认 | 不连接券商 |

## 目标概念架构

```text
用户入口（通义／夸克／钉钉，规划）
                ↓
         百炼工作流（规划）
       ┌────────┴────────┐
新闻／舆情 Agent     公告／数据 Agent
       └────────┬────────┘
             主管 Agent
                  ↓
             风险 Agent
                  ↓
            用户人工复核

横向能力：合同校验 · 证据账本 · 魔搭评测 · 运行观测
底层工具：经授权的 A 股数据适配器与可选外部工具
```

目标架构不是把所有产品名称堆在一张图上，而是让每项能力解决一个明确问题：

- 通义千问：结构化抽取、比较、解释。
- 百炼：并行节点、条件分支、工具调用与运行追踪。
- 魔搭：模型／测试集管理与评测。
- 钉钉：专业团队通知、复核与人工门禁。
- 通义／夸克：完成合规评估后的消费者入口。
- 无影／QoderWork：开发、演示和运行环境。

详细映射见 [阿里技术映射](05_ALIBABA_TECHNOLOGY_MAP.md)。

## 六个技术层

### 1. 体验层

服务非技术用户快速判断：

- 主页面只显示事件、证据状态和风险等级。
- 右侧报告展示原因、来源、冲突与未知项。
- 图表用于解释“数据如何触发关注”，不能装饰性造结论。

### 2. Agent 责任层

来源专项 Agent 只能写自己的简报；主管只能比较简报；风险 Agent 只能解释综合结果。层级与权限见 [Agent 层级](02_AGENT_HIERARCHY.md)。

### 3. 编排层

`IMPLEMENTED · MOCK` 的状态机包含：

1. 事件入队
2. 专项 Agent 逻辑并行
3. 结构化简报提交
4. 主管综合与冲突检查
5. 风险映射
6. 用户报告就绪

未来用百炼节点替代模拟节点时，合同与安全门禁保持不变。

### 4. 证据与合同层

所有下游结论必须引用上游 ID。系统需要区分：

- 事实 `fact`
- 推断 `inference`
- 未知 `unknown`
- 冲突 `conflict`

合同详情见 [合同与安全](04_CONTRACTS_AND_SAFETY.md)。

### 5. A 股适配层

官方公告是一级证据；新闻和企业信息用于交叉核验；热搜只作事件触发。任何来源失败都要显式降级，不能用 MOCK 冒充 LIVE。详见 [A 股适配层](06_A_SHARE_ADAPTER_LAYER.md)。

### 6. 评测与治理层

当前组织实验只证明“如何比较”，不证明哪个组织普遍更优。正式评测需要固定任务集、模型和提示词版本，多次重复运行并报告不确定性。

## 关键安全边界

- 浏览器不得持有服务端 API Key。
- 主管 Agent 不得绕过专项 Agent 直接补写事实。
- 热搜声量不得直接转成风险结论。
- 单一来源超时不能被解释为“没有风险”。
- 证据冲突必须保留，不能平均成确定答案。
- 用户确认只记录阅读，不产生交易。

## 路演可用表述

> 当前原型真实实现了 Agent 分工、结构化交接和故障降级，但模型推理与数据输入仍为 MOCK。目标方案可以在不改变核心合同的前提下，将节点迁移到百炼和通义千问，并通过授权的数据适配器服务 A 股信息核验。
