# Agent 层级、职责与权限

> 当前状态：`IMPLEMENTED · MOCK`  
> 在线模型调用：`PLANNED`

## Agent 不等于平台

当前四个 Agent 是同一应用里的四种**逻辑职责、输入输出合同和权限边界**，不是四个网站，也不是四个已经在线运行的大模型。

未来可以使用同一个通义千问模型，通过不同角色提示词、工具权限和结构化输出形成四个角色，再由百炼完成编排。

## 层级

```text
L0 事件入口
   ↓
L1 新闻／舆情 Agent ─┐
                     ├→ L2 主管 Agent → L3 风险解释 Agent → 用户门禁
L1 公告／数据 Agent ─┘
```

## 四个角色

| 层级 | 角色 | 只负责 | 标准输出 | 禁止事项 |
| --- | --- | --- | --- | --- |
| L1 | 新闻／舆情 Agent | 新闻、公开讨论、热度线索、来源独立性 | `EvidenceBrief` | 修改公告事实、给交易建议 |
| L1 | 公告／数据 Agent | 交易所公告、财务字段、企业主体信息 | `EvidenceBrief` | 推测舆论动机、形成最终结论 |
| L2 | 主管 Agent | 一致点、冲突、未知项、证据覆盖 | `SupervisorSynthesis` | 自行抓取新证据、删除分歧 |
| L3 | 风险解释 Agent | 把综合结果翻译成风险说明和核验清单 | `UserRiskReport` | 推荐目标仓位、连接券商、自动下单 |

L1 两个 Agent 可以逻辑并行，但不能互改对方的简报。主管必须等到两份简报都返回，或其中一份进入可见的降级状态后才能继续。

## 写入边界

| 角色 | 可写命名空间 | 只读依赖 |
| --- | --- | --- |
| 新闻／舆情 Agent | `/sources/news/*`、`/briefs/news/*` | `Event` |
| 公告／数据 Agent | `/sources/disclosures/*`、`/briefs/data/*` | `Event` |
| 主管 Agent | `/synthesis/*`、`/conflicts/*` | 两份 `EvidenceBrief` |
| 风险解释 Agent | `/reports/risk/*`、`/governance/review/*` | `SupervisorSynthesis`、虚拟暴露快照 |

这些边界当前由 UI、代码与合同表现；生产版本还需要后端身份、能力令牌与授权策略强制执行。

## 来源专项分工

### 新闻／舆情 Agent

建议将输入划分为：

- 授权新闻：二级证据。
- 公开热度／趋势：只作触发。
- 社交传闻：默认未验证。

它必须回答：

1. 消息最早来自哪里？
2. 多个报道是否只是同一来源转载？
3. 哪些是可验证事实，哪些是情绪或推测？
4. 是否存在与官方公告不一致的说法？

### 公告／数据 Agent

建议优先级：

1. 交易所和公司正式公告。
2. 结构化财务字段。
3. 企业主体与公开工商信息。

它必须回答：

1. 是否存在一级来源？
2. 数值的单位、期间和口径是什么？
3. 是否有更正、补充公告或数据过期？
4. “未找到公告”是否被错误理解为“事件为假”？

### 主管 Agent

主管不追求“统一口径”，而追求**可追踪的分歧**：

- `agreement`：两边能共同支持的最弱结论。
- `conflicts`：方向、时间、主体或口径冲突。
- `missing`：裁决冲突仍缺少的证据。
- `decision`：升级关注、等待核验或隔离来源。

### 风险解释 Agent

风险解释 Agent 面向普通用户，重点展示：

- 发生了什么。
- 哪些已经证实。
- 哪些仍然未知。
- 用户下一步应该核对什么。

它不回答“该买还是该卖”。

## 工具与 Agent 的关系

MCP、公告接口或趋势聚合器都是 Agent 可以调用的**工具**，不是新的决策层。工具返回的内容仍需经过来源分级、合同校验和主管复核。

推荐 UI 连接状态：

- `MOCK`
- `AVAILABLE · NOT CONNECTED`
- `CONNECTED`
- `DEGRADED`
- `AUTH REQUIRED`

禁止为了视觉效果虚构 `CONNECTED`。

## 为什么不继续增加 Agent

本次路演的创新点是责任分工和证据交接，不是 Agent 数量。只有当新角色同时满足以下条件时才应增加：

1. 拥有独立来源或权限；
2. 有不同的失败模式；
3. 能定义明确合同；
4. 不会重复现有角色。

冲突复核 Worker 可以作为未来条件分支，但不应成为日常固定第五个 Agent。
